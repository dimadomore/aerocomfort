# Master plan — Aerocomfort

> Дата: 2026-06-13. Это «северная звезда» проекта: видение, принципы, дорожная карта, риски, метрики.
> Детали — в соседних документах (04–08). План живой: ответы Джона ([02-questions-for-john.md](02-questions-for-john.md)) добавляются как вставные модули, без переделок.

## 1. Видение в одном абзаце

Быстрый, статический, мультиязычный (EN/ES) сайт мастера-частника HVAC в Costa Blanca. Он внушает доверие с первого экрана, мгновенно даёт связаться (WhatsApp / звонок / форма), собирает корректные лиды (валидный телефон!), отлично индексируется поисковиками и читается ИИ-агентами, и обновляется промптами. Переход со старого Tilda-сайта — без потери позиций и конверсий.

## 2. Принципы (по ним принимаем все решения)

1. **Лид важнее красоты.** Каждый экран отвечает на «как с ними связаться» и «почему им можно доверять». WhatsApp — герой.
2. **Mobile-first.** Аудитория 40+ приходит с рекламы со смартфонов. Крупно, читаемо, большие тач-таргеты, липкая панель действий.
3. **Скорость как фича.** Статика, ноль лишнего JS, ленивая загрузка третьих сторон (Elfsight). Цель — зелёные Core Web Vitals и Lighthouse 95–100.
4. **Доверие через конкретику.** Реальные фото работ и мастера, числа (лет опыта, установок, рейтинг), сертификаты, гарантия, названия районов. Никакой «воды».
5. **Проще — лучше.** Не оверинжинирим. Минимум зависимостей, понятная структура, один источник правды для контента.
6. **Промптуемость.** Контент отделён от кода (Astro content collections + data-файлы). Изменить оффер, добавить отзыв, написать статью — правка одного файла или один промпт.
7. **SEO + AEO с первого дня.** Структура, семантика, structured data, hreflang — не «потом», а в фундаменте.
8. **Без «ИИ-эстетики».** Никаких фиолетовых градиентов, глассморфизма, стоковых 3D-человечков. См. [04-design-system.md](04-design-system.md).

## 3. Дорожная карта (фазы)

Каждая фаза — самостоятельный, деплоящийся инкремент. Можно остановиться после Фазы 1 и уже заменить Tilda.

### Фаза 0 — Фундамент ✅/🔄
- ✅ Репозиторий, ветки main/dev, CI, хостинг Cloudflare, staging-домен `aero.dimadomore.com`.
- 🔄 Дизайн-токены (CSS-переменные) + Tailwind-конфиг, шрифты, базовый Layout, i18n-каркас (EN корень / ES `/es`), структура content collections, SEO-база (мета, OG, sitemap, robots, фреймворк schema.org), консент+аналитика-каркас, endpoint форм (Cloudflare Worker) с валидацией телефона, обёртка ленивой загрузки Elfsight, заглушки юридических страниц.

### Фаза 1 — Ядро сайта (MVP, можно запускать) 
Страницы (EN+ES): Главная, Услуги (обзор + по одной на каждую: установка / ремонт / обслуживание / чистка), Офферы, О нас / доверие, FAQ, Контакты, `/thank-you`, юридические (Privacy, Cookies, Aviso Legal). Сквозные элементы: шапка, футер, чат-лончер с быстрыми действиями, липкая мобильная панель, формы с валидным телефоном. → Этого достаточно, чтобы заменить старый сайт.

### Фаза 2 — Локальное SEO и бренды
- Страницы зон обслуживания (Torrevieja, Orihuela Costa, Alicante, …) — главный рычаг локального SEO.
- Страницы брендов (Daikin, Mitsubishi Electric, LG, Panasonic, Giatsu…) — под запросы «бренд + установка».

### Фаза 3 — Блог и автоматизация
- Блог (вечнозелёные статьи + сезонные советы).
- Пайплайн «Telegram-бот → фото+текст → статья на EN/ES → публикация» (идея Джона). См. [08-content-and-assets.md](08-content-and-assets.md).

### Фаза 4 — Миграция и запуск
- Карта 301-редиректов, hreflang QA, перенос/проверка конверсий Google Ads, Search Console, перенос DNS `aerocomfort.es` в Cloudflare, мгновенное переключение, мониторинг, вывод Tilda из эксплуатации. См. [07-migration.md](07-migration.md).

### Фаза 5 — Уход и рост
- Инструкция по поддержке (deliverable из брифа), контент-календарь, генерация отзывов, мониторинг позиций/скорости.

## 4. Что ещё важно учесть (на мой взгляд) — то, чего не было в брифе

Это вещи, которые делают разницу между «сайт-визитка» и «машина для лидов», и которые легко упустить:

1. **NAP-консистентность.** Название/адрес/телефон должны побайтово совпадать на сайте, в Google Business Profile и в каталогах. Google сверяет — расхождения роняют локальную выдачу.
2. **Параллельная конверсионная цель — `/thank-you`.** Старый сайт её использует (почти наверняка это цель в Google Ads). Сохраняем URL и логику, иначе реклама «ослепнет».
3. **Сохранить ВСЕ события конверсий.** Не только форму: клик по WhatsApp и клик по телефону на мобильном — это тоже конверсии. На новом сайте навешиваем их явно. См. [06-seo-aeo.md](06-seo-aeo.md).
4. **Consent Mode v2 (GDPR/EU).** Без корректного баннера согласия Google Ads/Analytics в ЕС работают ограниченно и это юридический риск. Делаем легко и правильно.
5. **Защита форм от спама** — Cloudflare Turnstile (бесплатно, невидимо) + honeypot. Иначе Джона завалит мусором, и он перестанет доверять заявкам.
6. **Надёжность доставки лида.** Лид уходит и на email, и дублируется в Google Sheets (мини-CRM), плюс опционально уведомление в WhatsApp/Telegram. Если один канал упал — лид не потерян.
7. **Aviso Legal** — в Испании юридически обязательная страница для бизнеса (LSSI-CE), отдельно от Privacy/Cookies.
8. **Почта на домене** `info@aerocomfort.es` через Cloudflare Email Routing (бесплатно) — выглядит профессиональнее gmail и не привязывает бизнес к личной почте. Рекомендация.
9. **hreflang EN↔ES** — на старом сайте его, похоже, нет. Это даёт прирост: Google перестанет «путать» языковые версии. Лёгкая победа.
10. **Доступность (a11y).** Для 40+ это не «галочка», а конверсия: крупный шрифт (база 18px), контраст AA, тач-таргеты ≥44px, видимый фокус, уважение `prefers-reduced-motion`.
11. **Открытый граф (OG-картинки).** Когда ссылку кидают в WhatsApp (а её будут кидать!), должна красиво разворачиваться карточка. Генерим OG-образы.
12. **404 и внутренняя перелинковка.** Грамотная страница 404 с путями назад; перелинковка услуга↔зона↔бренд — и для людей, и для SEO/AEO.
13. **`llms.txt` + чистая семантика** — чтобы ИИ-агенты (ChatGPT, Perplexity, Google AI) корректно «понимали» бизнес и рекомендовали его. См. [06-seo-aeo.md](06-seo-aeo.md).
14. **Один источник правды для бизнес-данных** (`src/data/business.*`): телефон, WhatsApp, email, часы, зоны, соцсети, реквизиты. Используется в шапке, футере, schema.org, страницах. Меняешь в одном месте — меняется везде.
15. **Версионирование контента и бэкап.** Всё в git — но также продумать, чтобы правки Джона (если он будет править) не ломали сборку: контент в простых YAML/MD с понятными полями.

## 5. Метрики успеха

| Цель | Метрика | Таргет |
|---|---|---|
| Скорость | Lighthouse (mobile), CWV | Perf ≥95, LCP <2.5s, INP <200ms, CLS <0.1 |
| Без просадки SEO | Позиции по топ-запросам (Search Console) | Не ниже старого через 4–8 недель, рост далее |
| Конверсии | События: форма, WhatsApp-клик, тел-клик, `/thank-you` | Паритет или рост к старому сайту |
| Качество лидов | Доля валидных телефонов | Резкий рост (валидация E.164) |
| AEO | Корректное упоминание бизнеса ИИ-агентами | Бизнес «узнаётся», данные верные |
| Доступность | axe / Lighthouse a11y | ≥95, ключевые сценарии без барьеров |

## 6. Реестр рисков

| Риск | Влияние | Митигация |
|---|---|---|
| Просадка позиций при переезде | Высокое | Карта редиректов, паритет контента/ключей, hreflang, staged-запуск, мониторинг до/после, Tilda не гасим до проверки |
| Потеря конверсий Google Ads | Высокое | Инвентаризация текущих конверсий до переезда, повтор событий 1:1, сохранение `/thank-you`, тест в Tag Assistant |
| Битые телефоны лидов | Среднее | libphonenumber-валидация, нормализация E.164, маска по стране, блок отправки невалидного |
| Elfsight роняет скорость | Среднее | Ленивая загрузка по входу в вьюпорт, плейсхолдер; путь к статической замене описан |
| GDPR/консент | Среднее | Consent Mode v2, баннер, юридические страницы |
| Рассинхрон EN/ES | Среднее | Структура контента с парными файлами, чек-лист «обе версии» в DoD |
| Континуитет почты/DNS | Среднее | Email Routing настроить до переноса; перенос DNS заранее с низким TTL, текущий сайт не трогаем |
